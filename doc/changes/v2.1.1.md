# v2.1.1

Date: 2026-09-06

Second performance pass. No surface changes; every public signature and behaviour is the same,
only the work per render / per frame dropped.

## columnState: normalized config is memoized (the main item)

- `normalize()` used to re-derive the whole config (filter unknown keys, append missing
  columns, pin fixed ones, rebuild visible/width/filter/groups) on EVERY render of every
  subscriber - CardList, ColumnsMenu, ColumnDots, the Toolbar over `listSource`, columnGrid's
  visible-count check, plus once more inside `visibleKeys()`. The consumers then paid a
  `JSON.stringify` of the result per render just to get a stable identity back.
- Now the normalized config is cached by the IDENTITY of the persisted fields
  (`order/visible/width/sort/filter/groups`). `commit()` and storage hydration both replace
  those references, so "a field reference changed" is exactly "the config changed". Between
  commits `getConfig()`, `useConfig()`, `visibleKeys()` and (without an active preview)
  `useDisplayConfig()` return the same objects; with a preview the overlay is cached on
  `(config, preview order)` identity.
- CardList and ColumnsMenu key their memos on the config/keys identity directly - the two
  `JSON.stringify` per render are gone. ColumnDots builds its column map once per descriptor set.
- Contract note (was already true, now load-bearing): the config handed out is shared, callers
  spread it, never mutate it. Pinned by a new case in `__test/createColumnState.test.ts`.

## Smaller items

- `LeftModal` slide animation runs on `requestAnimationFrame` paced by elapsed time instead of a
  `sleepAsync(10)` + `setState` loop (~100 renders/s that never aligned with paint and were
  throttled to >=1s ticks in a background tab). Same 40px-per-10ms pace.
- `createGridChrome().Chrome` builds its command model (context, filtered app commands, sorted
  groups, the built-in lists) only while the popover is open; a closed trigger re-rendered on
  every grid attach/detach and feedback tick and rebuilt all of it for nothing.
- `useDraggableApi` writes its callback refs during render like its other refs, instead of a
  no-deps passive effect scheduled on every render of every draggable.

- Jest 57 suites / 289 tests (one new).
- `npm run build` with declaration check and package probes; QA stand smoke on the columnState
