# v1.1.0

Date: 2026-08-23

- Fixed: `FloatingWindow` froze a plain element child at its first render. Every
  child was wrapped in an internal memo keyed on the window's `update` counter,
  which stays `0` for the non-render-prop form, so the comparator never saw a
  change. Plain children now render normally; the render-prop form keeps its
  documented freeze between `update` bumps.
- Fixed: a `FloatingWindow` opened from inside another `FloatingWindow` (the
  clientBacktest "user strategies" window's `history`/`remote` buttons) sat under
  its opener and could not be raised. Two causes. Effects run children-first, so
  when both mounted in one commit the nested window registered before its opener
  and the opener's plain push landed on top; entries now register in creation
  (render) order. And a press inside the nested window, which portals to body,
  still bubbled through React to the opener's `onWindowMouseDown`/`onWindowPointerDown`,
  which re-raised the opener right after the nested window; the innermost window
  now claims the native press and an ancestor only raises when the press is
  inside its own DOM (its content or an embedded `portal={false}` child, which
  keeps raising its host).
- Changed: `useDraggableApi` announces `onDragStart` where the drag actually
  begins. It used to fire from `onMouseDown`/`onTouchStart`, before the `holdMs`
  gate, so with the default `holdMs` of 500 every plain click produced a start
  with no matching `onDragEnd`. With `holdMs: 0` the start is still synchronous
  on pointer-down, which is the contract `DragBox`, `useReorder` and
  `useReorderBoard` depend on.
- Changed: `Button`'s `keyForSave` now means what it means on `FloatingWindow`
  and `FResizableReact` -- the open/closed state rides an `ObservableMap`
  registered in `memoryCache`, and the application decides when storage is
  written. It previously used a private module object, a second undeclared
  persistence path that made the same prop name mean "until reload" on this
  component only. The map is reachable as `memoryMaps.button`.
- Fixed: `renderByRevers` was missing from the `./react` subpath while the root
  barrel exported it.
- Added: a barrel-parity probe over the subpath entrypoints. The subpath barrels
  are hand-maintained lists over modules the root `export *` already covers, so
  they drift silently. The probe compares runtime bindings in both directions and
  pins `./native` as the documented exception -- it must stay OUT of the root
  barrel to keep its DOM/CSS/ag-grid-free guarantee.
- Added: an isolation guard for `wenay-react2/native`. The subpath exists for the
  renderer-neutral guarantee, but nothing enforced it; a single value import from
  the shared tree would drag `react-dom`, ag-grid or a CSS side effect into every
  React Native consumer without the packaging probes noticing. The guard also
  pins its own detector so it cannot silently stop catching violations.
- Internal: the mouse and touch drag loops of `useFloatingWindowController`
  shared six byte-identical clamp lines each; both now call one helper. Two dead
  ternaries dropped from `snapPreviewStyle`. Release scratch under `target/` is
  gitignored, and Jest maps CSS imports to a stub so tests can reach the root
  barrel at all.
- Verification: all 48 Jest suites and 196 tests, strict TypeScript checks over
  both the published surface and the test tree, clean production package build,
  package entrypoint probe, and packed TypeScript/esbuild consumer probe passed.

## Packaging

- Fixed: the published package could not be loaded by Node at all -- neither
  `import` nor `require`. The manifest had no `"type"`, so Node parsed the ESM
  emit as CommonJS, and `moduleResolution: "Bundler"` emitted extensionless
  relative imports, which Node ESM does not resolve either. All relative imports
  now carry `.js` (the convention `src/native` already followed) and the manifest
  declares `"type": "module"`. `./core`, `./react` and `./native` load in Node
  now; `./grid`, `./windows`, `./logs`, `./communication` and the root barrel
  still require a bundler, because they import `style.css` as a side effect and
  no Node loader resolves that. That boundary is deliberate and documented -- the
  CSS imports cannot be removed without breaking every current consumer.
- Added: the packed-consumer probe imports the tarball through Node's own loader
  for the three CSS-free entrypoints. The three verification layers that existed
  (Jest, esbuild probes, tsc probes) all read the package as a bundler would,
  which is why the format defect survived several review rounds.
- Fixed: `./demo/stand` did not resolve for consumers. `socket.io-client` is
  imported by two published files but was only a devDependency, and the release
  step deletes devDependencies from the published manifest. It is an
  `optionalDependency` now -- an *optional peer* would not have fixed it, because
  no package manager auto-installs optional peers.
- Added: `ag-grid-community`, `ag-grid-react` and `wenay-common2` are declared as
  `peerDependencies` alongside their existing `dependencies` entries. Their
  objects cross the public API (`ModuleRegistry` and `GridApi` belong to one copy;
  `Params`/`Observe`/Replay types appear in `/logs` and `/react` signatures), so a
  duplicate copy breaks at runtime the same way two Reacts did. Keeping the
  `dependencies` entry means no installation changes for anyone -- yarn and
  pnpm <= 7 never auto-install peers -- while pnpm >= 8 and yarn berry now resolve
  the library to the application's copy instead of silently loading a second one.
- Added: `./styles`, `./styles/tokens` and `./styles/menu-right` to `exports`.
  The CSS shipped in the package but no `exports` path led to it, so a consumer of
  `./core` or `./react` could not reach the stylesheet at all.
- Removed: `engines.vscode`, the `tsconfig_lib.json` copy published inside `lib/`,
  and its now-unused source.

## Fixed

- `structEqual` treated any two `Date` values as equal -- they have no own keys,
  so the plain-object branch compared empty key sets. The cache revives ISO
  strings into `Date` on load, so dates really do reach these trees.
- `updateBy` did not advance the version when nothing was subscribed yet. A
  component reads the version during render and React re-reads it right after
  subscribing, so a mutation landing in that window compared equal and the update
  was lost until the next `renderBy`.
- `deepMergeWithMap` lost data three ways: the visited map stored an empty
  placeholder it never filled in (so a subtree reachable twice merged into `{}`),
  a truthy primitive was treated as a merge base (silently dropping the whole
  default subtree), and the default's arrays were aliased into persisted state.
- A context menu opened on any plain left click during the first 300 ms of a
  layer's life -- the double-click timestamp ref was seeded with `Date.now()`.
  In both `menuMouse` and `menuR`.
- `ParamsEditor` dropped the parameter type for single parameters, so a string
  date rendered as a plain text field instead of the time control.
- `gridChrome` declared two components inside the `Chrome` body, giving them a new
  type identity on every render: React remounted the whole popover subtree, which
  is visible as lost button focus after any command with `closeOnRun: false`.
  A `useId` call also sat after an early return.
- `columnState.detach()` cleared the pending debounced grid read without flushing
  it, so a column resize followed by a route change inside `saveMs` was lost.
- `useReorder` left the preview order applied when it unmounted mid-drag.
- Touch long-press recorded its start coordinates only when the previous gesture
  had succeeded, so an aborted gesture measured the next one against stale
  coordinates; the scroll threshold was also a fraction of `pageX`, making it
  depend on where the page was touched. Now a pixel threshold, in both copies.
- `inputAutoStep` wrote the string `"NaN"` into a cleared field and `step="null"`
  onto an element that had no `step` attribute; the step is also recalculated on
  `input`, so paste and spinner clicks no longer leave it stale.
- `ParamsArrayEdit` mutated its state array and passed the same reference to
  `setParams`, so React bailed out and edits never re-rendered.
- Two async loaders in `Other.tsx` set state after unmount.
- `Button`'s persisted open state was written from inside a state updater, which
  synchronously notified subscribers -- a second `Button` on the same `keyForSave`
  called `setState` during the first one's render.
- The chart crosshair stayed frozen at its last position when the pointer left
  the canvas.
- `useCacheMapPersistence` re-ran `load()` when only `delay` changed, merging
  storage over current values and rolling back unsaved edits.
- Focus could leave a trapped overlay on a plain Tab when focus sat outside it.
- Grabbing a nested window's resize handle raised its opener over it: the handles
  are siblings of the window body, so the press was never claimed.

## Performance

- The chart answers a pointer move by blitting a cached data layer and repainting
  only the crosshair, instead of re-running the LOD scan over every dataset.
  `Renderer.drawPanelCrosshair` and `createInteraction`'s `onCrosshairMoved` are
  additive; a custom renderer without them keeps the old single-pass behaviour.
- `getMinMaxInRange` binary-searches the min/max chunks instead of scanning all of
  them; it runs per dataset per panel on every dirty frame.
- `Sparkline` hashes its drawing inputs instead of `JSON.stringify`-ing every
  point of every series on each React render.
- Axis time labels use one module-level `Intl.DateTimeFormat` plus a bounded cache
  rather than `toLocaleTimeString` per label per frame.
- Fill gradients are cached per context and geometry instead of being rebuilt for
  every filled series on every frame.
- `frameStamp` mixes positionally, so compensating changes across datasets can no
  longer produce the same stamp and skip a frame.
- The logs context value is memoised and the logs table has a stable `getRowId`,
  so one new log no longer rebuilds all 500 auto-height rows.
- The settings dialog memoises its filtered tree; it used to walk every section's
  `render()` on renders that had nothing to do with the query, including every
  pointermove of a splitter drag.
- Async submenu loading no longer restarts on every parent render.
- All outside-click areas share one pair of document listeners instead of two per
  instance, matching what `useKeyboard` already did.
- `useContractSlot` keeps a slot's status stable when the runtime event concerned
  a different slot.

## Added

- `wenay-react2/react` exports the persistence surface (`memoryCache`,
  `useCacheMapPersistence`, `memoryGetOrCreate` and friends). The documented
  contract -- the library never writes storage on its own, the application decides
  when -- was unreachable from any subpath barrel, so switching it on meant
  importing the whole library.
- `wenay-react2/core` exports `tokensVar`, the `var()` form of the design tokens,
  and the ag-grid theme is built from it. Overriding `--grid-*` (or
  `:root[data-theme=...]`) re-skins the grid now, which previously stayed dark
  while windows, menus and dialogs followed the application's theme.
- `wenay-react2/react` exports the shared `useElementSize`/`useResizeObserver`.
- `createCacheMapWithStorage` returns a `dispose()`.

## Internal

- `FloatingWindow.tsx` split from 1259 to 911 lines: geometry, the portal, the
  window chrome and the unrelated `DragBox` live in their own modules now, all
  re-exported so import paths are unchanged. The drag loop and the persistence
  effect were deliberately left in place -- extracting them needs about ten
  setters and refs each, which fragments the controller rather than splitting it.
- `useReplay.ts` grew two shared lifecycle shells; the individual adapters shrank
  by 50-68% and the identity-reset/cleanup/route-phase logic exists once.
- `createPersistedController` owns the read/subscribe/announce idiom for all five
  persisted controllers and adds what none of them had: a `version`/`migrate` hook
  for stored configs.
- `myChart` follows its container -- it measured the container once at creation,
  so a chart in a resizable panel kept its first bitmap forever. The DPR and
  resize plumbing is shared with `Sparkline` now.
- Six copies of `cx`/`classNames`, and the second copy of the logs colour values,
  collapsed into single definitions.
- `FloatingWindowTypes` moved into `utils`, closing the one edge where a utils
  leaf reached up into the component layer.
- Type-parity, native/web column-parity, persisted-controller, canvas-surface,
  shared-listener and reactivity-core test suites added; the tokens mirror covers
  `tokens.grid` now.

## Verification

All 55 Jest suites and 241 tests, strict TypeScript over both the published
surface and the test tree, a clean production build with the entrypoint,
packed-consumer and Node-ESM probes, and the QA stand loading without console
errors. Dependencies updated: `wenay-common2` 2.12.0, ag-grid 36.1.0, Vite 8.2.2.

Known upstream issue: `wenay-common2` 2.12.0 loses the replay surface at the type
level for an RPC facade member. `createRpcClientHub` composes
`ClientAPIAll<DeepSocketListenSmart<T>>`; the inner pass correctly produces
`ReplaySocketListen` (whose method is `since`), and the outer pass re-runs the
`IsReplayMember` detector, which looks for the server-side name `getSince` and so
misses. The runtime is unaffected -- the server exposes both surfaces under one
key -- but the QA stand needs a cast until the detector accepts either name.
