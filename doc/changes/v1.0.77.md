# v1.0.77

Date: 2026-08-05

- Changed: `FloatingWindow` now uses a fixed body-portal host and an absolute
  window in viewport coordinates by default. Pressing an older window raises its
  complete isolated stacking context; `portal={false}` retains the rare embedded behavior.
- Fixed: window content is no longer trapped by an application ancestor's
  `transform`, `overflow`, or z-index context. `OutsideClickArea` recognizes
  logically nested portal interactions, and the optional close control is now an
  accessible button.
- Added: Windows-style maximize/restore from the title-bar control, double click,
  or two taps; `Alt+Enter`, keyboard move/resize, active/mode/geometry callbacks,
  close reasons with `beforeClose`, and group-aware `useFloatingWindowManager`.
- Added: a Windows 11-like top-centre Snap Layout picker with half/quarter targets,
  preview, responsive viewport geometry, and unsnap-to-previous-size drag behavior.
- Added: `WindowPortal` for owner-scoped menus/tooltips. Nested modal overlays now
  arbitrate Escape/outside clicks to the top layer and trap/restore focus.
- QA: active card 52 covers two overlapping windows, extreme descendant z-index,
  maximize/restore, scoped popups, Snap Layout, viewport edges, and close chrome.
