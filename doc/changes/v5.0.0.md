# v5.0.0 — wenay-calls split and optional ag-grid

Date: 2026-09-24

A permanent major migration note. Migrating 3.x or 4.x code is one CLI run:
`doc/WENAY_REACT2_RENAMES.md`, "5.0.0 migration cut". Source: the owner's request of 2026-09-24
to split the library, decided after comparing the maintainer proposal with an independent
architecture review. Both agreed: carve out only the call UI; keep grid, core and UI together
because they share module-level state (`memoryCache`, the persisted maps, the ag-grid module
registry, the toolbar and settings registries); make ag-grid an optional peer.

## Breaking

- The call UI is the new package `wenay-calls` 1.0.0 (`packages/wenay-calls` in this
  repository): the `./communication` entry, `./styles/communication`, `./demo/peer-media`,
  `./demo/peer-conference`, and `useRouteState` / `RouteLogEntry` from `./react`.
- `ag-grid-community` and `ag-grid-react` are optional peers instead of dependencies. Apps that
  use `./grid` or `./logs` install them; every other app skips about 21 MB (ag-grid-community
  20.5 MB unpacked plus ag-grid-react 0.8 MB).

## wenay-calls 1.0.0

- Imports only react and wenay-common2 (peers only) and never wenay-react2: two copies of this
  package's module-level state would split silently. `__test/barrelParity.test.ts` and the bundle
  probe boundary (`calls`: no byte from `src/`) guard it.
- `VideoCall` with `labels`, `useVideoCallController`, `useMediaSource`, `usePeer`, `usePeerCalls`,
  `usePeerPresence`, `useRouteState`, the two peer demos and the stylesheet; the conference demo
  now imports `listen` from the narrow `wenay-common2/listen` instead of the client barrel.
- Built by `npm run build:calls` (tsc, stylesheet, then `scripts/calls-package-probe.mjs`:
  tarball contents without sources, exports targets, peers only, TypeScript subpath types,
  esbuild, Node ESM) and published from `packages/wenay-calls`. Its README carries its changes.

## Migration CLI

- Handles the 5.0.0 moves next to root imports and the 4.0.0 renames: whole moved modules are
  re-pointed (side-effect stylesheet imports included), root imports of call names are grouped
  under `wenay-calls`, a `./react` import containing `useRouteState` is split, and a dynamic
  import of a moved module is reported. A test pins the moved-name list to the actual
  `wenay-calls` entry. 22 node tests; the packed-consumer probe runs the CLI from the tarball.

## Repository

- The QA stand, tests, tsc (`tsconfig.qa-check.json` paths), Vite (aliases) and Jest
  (moduleNameMapper) resolve `wenay-calls` by name from source. The internal `hooks/index.ts`
  barrel is gone, `components/index.ts` no longer re-exports the call UI, and the stand imports
  public entries.
- CI builds both packages; `npm run typecheck` includes `packages/wenay-calls`.

## Kept deliberately

- `react-rnd` / `re-resizable` stay dependencies: most entries use them and they weigh 0.7 MB.
- `wenay-exchange` stays a dependency and peer, as the owner asked. Open question: no code of this
  package imports it, so today it only forces an install.

## Verification

Three TypeScript configurations (source and stand, tests, wenay-calls); Jest 74 suites / 363 tests;
migration CLI 22 tests; wenay-react2 build with the entrypoint probe (11 entries, no root) and the
packed-consumer probe (including the 5.0.0 CLI moves); wenay-calls build with its consumer probe
(23 files); bundle boundary probe (`calls` 8.8 KB gzip, no wenay-react2 bytes). QA stand: 73 cards,
card 60 rendered with the `wenay-calls/styles` stylesheet, presence edges on card 42, a
`#video-calls` room created and closed against the Vite backend; no new console or server errors.
