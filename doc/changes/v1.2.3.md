# v1.2.3

Date: 2026-08-25

- Fixed: the rest of the "degenerate stored/measured state outranks a prop" family that 1.2.2 opened, five confirmed cases each with a test that fails without its fix:
  - `FResizableReact`: a stored size won over the prop unconditionally, so `size={{width: 0}}` on a pre-measurement render persisted a 0 that collapsed the box. Judged against the caller's `minWidth`/`minHeight` (or re-resizable's 10px floor), repaired from the prop, resize deltas floored on the way in.
  - Context menu: the vertical clamp had no floor (the horizontal twin got one in 1.2.0); a menu taller than the viewport is now floored at the top edge.
  - Minimized window (`display:none`) measured zeros in the viewport clamp and `minimized` was not in the effect deps, so restore never re-clamped a window persisted offscreen.
  - Snap hydration checked `typeof window` but not `viewportUnusable()`.
  - Chart `resizePanel` divided by a container height of 0 before the first `ResizeObserver` tick; the NaN spread through every `layoutPanels()` pass. `isUsableDimension` now rejects NaN.
  - `setResizeableElement` baked `defaultWidth` from a hidden element; it is now captured on the first observation with a layout.
- Deliberately unchanged: `RightMenu`'s drag-end persist can store an offset from a degenerate rect, but `containerStyle` re-clamps every render and the next drag overwrites it.
- Verification: 57 Jest suites / 266 tests (10 new), both typecheck configs, probes, live stand.
