# v2.3.0

Date: 2026-09-06

Architecture follow-ups that were parked after the 2.0.0 cut: the ownership/lifecycle items
from the grid review and the two file splits. Three of them change behaviour at an edge;
each is listed under "Changed" with the old and new rule.

## Changed (behaviour at an edge, no renames)

- **`AgGridTable`: row identity has one owner.** With a `controller`, the controller's `getId`
  is the grid's `getRowId`; a `getRowId` prop passed next to a controller is ignored (one
  development-mode warning). Before, the prop won, so the buffer keyed rows by one function
  and the grid matched transactions by another - updates could miss their rows. Without a
  controller the prop feeds the table's own overlay buffer exactly as before.
- **`createColumnGrid`: one controller, one grid.** The state follows the most recently
  attached table. Destroying an OLDER table (two `<Table>` mounts of one controller during a
  route transition) no longer detaches the newer, live grid. `dispose()` is now a full release:
  it detaches the attached grid, so no grid event reaches the state afterwards (it used to keep
  the grid listeners until that grid was destroyed).
- **columnState groups gate the desktop grid too.** A sub-column excluded from its group's
  enabled set was hidden in `visibleKeys()` / CardList / ColumnDots but still shown by ag-grid.
  `applyToGrid` now hides it as well, and `readFromGrid` does not fold that hide back as
  persisted `visible: false` (same rule as the presence gate). Table and cards agree.

## Internal

- `Settings/settingsTree.ts` (section descriptors, tree build, pure filter) and
  `Settings/searchText.tsx` (query normalisation with ru<->en layout variants, React-tree
  text extraction and cache, label highlighter) split out of `SettingsDialog.tsx` unchanged;
  the dialog file keeps the controller and the view. Types re-exported from the same place.
- `Toolbar/toolbarConfig.ts`: `normalizeToolbarConfig`, `sourceKeySet`, `mergeSourceOrder`,
  `sameOrder`, `SETTINGS_KEY`/`RESET_KEY` as pure functions over explicit inputs; `Toolbar.tsx`
  reads the persisted entry and the source and calls them.
- `__test/barrelParity.test.ts` gained the inverse assertion: the root-only runtime surface is
  a frozen, documented list, so a new module has to pick its subpath explicitly.
- New tests: `columnGridOwnership.test.tsx` (older-table destroy, dispose release) and a
  groups-on-grid case in `createColumnState.test.ts`.

## Verification
